# 講師向け: 開催前のリハーサル

[目次](../../README.md) | [English](../en/instructor.md)

標準構成はContainer Appsです。開催環境でプロビジョニング、SQL演習、アプリ操作、削除を通して確認し、リージョン・権限・クォータ・組織ポリシーをそろえてください。

専用サブスクリプション・予算・リソース作成権限・リージョン・2 vCore容量・AI Model Managementの利用権限を確認します。使う環境で`azure_ai >= 2.5.6`、ネイティブ`ai.search`の`ctid` API、6拡張、3モデルが実際に利用できることを確認してください。旧デモの未公開ヘルパーを使う構成は対象外です。

利用規約が未同意のクラスターでは、作成後のPortalでの同意と、構成フックが停止した場合の再開まで確認します。同意済みの環境の結果だけで初回も無人実行できるとは判断しないでください。[受講者向けの初回手順](01-deploy.md#初めてhorizondbをデプロイする場合)と、モデルの準備時間を進行に組み込みます。

空の専用HorizonDBで`sql/01-postgresql.sql`から`07-graph.sql`まで実行し、`08-verify.sql`の出力を確認します。18件すべて1536次元、両インデックス、パイプラインcompletedかつ3件、グラフ18件が期待値です。APIのHealthに加えてDesign My Roomを実行し、6段階の実トレース・モデル応答・予算内価格・エラー時にモック表示されないことを確認します。

参加者と同じ会場回線でTLS、DBのFirewall、アプリのIP制限、NATの固定送信元IP、Key Vaultのプライベート接続を確認します。`azd up`で空環境から初期化とアプリ配信まで通し、`azd down --purge`で専用グループ、Container Appsの管理用グループ、削除済みKey Vaultが残らないことを確認します。授業では`azd provision`→SQL演習→`azd deploy`の順にし、開催前にnpm準備を済ませます。作成、再起動、モデル準備、配信、推論の時間を測定してください。

Cloud Shellで開催する場合は、`AZURE_CLIENT_IP`とブラウザーの`AZURE_HTTP_CLIENT_IP`を分けて確認します。HTTPSでは両方のIPを許可し、DBにはブラウザー用のIPを追加しません。Cloud Shellからの自動動作確認と、参加者のブラウザーからの操作の両方を確認してください。

15分を超える待機に備え、講師の**別の演習専用クラスター**を用意しておきます。切り替えた場合は参加者がデプロイを完了したとは説明しません。共有スキーマへ各参加者のDDLを同時実行せず、読み取りデモか個別環境で進めます。AI機能が未提供の場合は開催前に解決し、当日にモックで代用しないでください。アプリのAzureデプロイだけが遅い場合はローカル版を使い、後でAzureの完了を別途確認します。

地域別の価格・推論クォータ・モデル応答によって時間と費用は変わります。削除完了の確認担当を決め、演習終了時にリソースグループが消えるまで確認します。

教材を変更した場合のローカル確認:

```bash
npm install
npm test
npm run prepare:zava
node --test zava/tests/deployment.test.mjs
az bicep build --file zava/infra/main.bicep --stdout >/dev/null
```

標準SQL・アプリ・リンクの8テストと、デプロイ補助の10テストがあります。ローカルテストに加え、Reactビルド、Bicep、azdの構成とパッケージ、実環境での動作を確認してください。[出典と参照版](../references.md)
