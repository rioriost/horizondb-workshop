```sql
SELECT alias, model_name, status FROM model_registry.model_list_all()
WHERE alias IN ('default-embedding', 'default-reranker', 'default-chat');
```

スクリプトは現行`ai.search`の引数と`ctid`出力を確認し、不足時は停止します。古い版は[公式の移行手順](https://learn.microsoft.com/azure/horizondb/ai/migrate-ai-schema)を参照してください。更新可能な版を講師が確認した場合だけ更新します。`CREATE EXTENSION`だけではサービスに未配信の関数は追加されません。

## 3. 検索からリランクへ（4分）

```sql
\i sql/04-search.sql
```

| クエリ | 注目点 |
| --- | --- |
| pgvectorの`<=>` | 日本語で椅子を探す。コサイン距離は**小さい**ほど近い |
| `ai.search(search_type => 'fulltext')` | 英語の単語でBM25検索。`rerank=false`ならモデル推論不要 |
| `ai.search(search_type => 'hybrid')` | BM25とベクトル検索をRRFで統合。スコアは**大きい**順 |
| 同じ検索に`rerank => true` | 候補の意味的関連度をリランカーで再評価 |
| 外側の`WHERE` | 200 USD以下の椅子だけ残す |

リランク前後の上位商品・応答時間を比べてください。結果が必ず入れ替わるとは限りません。ベクトル・BM25・RRF・リランカーのスコアは尺度が異なるため、数値を直接比較しません。

**重要:** 現行`ai.search`は`TABLE(ctid tid, match_type text, score real)`を返します。`p.ctid = s.ctid`で**同じSQL文の中で**元の行と結合し、アプリには永続的な主キー`p.id`を返します。更新で変わりうる`ctid`を保存してはいけません。

外側の`WHERE`は**検索後**のフィルターです。検索前のカテゴリ別候補確保や認可の代替ではありません。今回だけは全18件を候補にすることで取りこぼしを避けます。大規模データでは[検索段階にフィルターを入れるSQL](https://learn.microsoft.com/azure/horizondb/ai/hybrid-search)を検討してください。ハイブリッド検索の成功だけでは両方式の実行を保証しないため、`pg_indexes`と`match_type`も確認します。

BM25の設定は`english`なので全文検索の入力も英語にします。日本語の体験は多言語Embeddingを使うベクトル検索です。日本語全文検索の品質を保証する教材ではありません。

## 5. Durable AI Pipeline（3分）

```sql
\i sql/06-pipeline.sql
SELECT * FROM ai.status('workshop_embeddings');
\watch 2
```

3件だけを使い、`chunk_step → embed_step → table_sink`のパイプラインを定義します。`ai.run()`は非同期の実行受付です。`last_run_status`が`completed`か`failed`になるまで確認します。`\watch`はCtrl+Cで停止できますが、パイプラインそのものは停止しません。

`failed`なら出力件数だけ見て成功と扱わず、statusと講師のログ調査で原因を解消します。完了後:

```sql
SELECT count(*) AS chunks, count(embedding) AS embedded,
       min(vector_dims(embedding)), max(vector_dims(embedding))
FROM workshop.pipeline_output;
```

短文なので期待値は`3, 3, 1536, 1536`です。`*_step()`は遅延実行の定義、名前にstepのない関数は即時推論です。`incremental_column => 'updated_at'`が差分処理の基準になります。変更を再処理したいときはタイムスタンプも進めます。演習ではmanualを使い、実運用で自動追従したい場合は`on_change`と初回`ai.run()`を組み合わせます。

チャンクの`doc_id`はバッチ内の番号であり商品の主キーではありません。今回の出力は学習用で、アプリは第2節で生成した商品Embeddingを使います。

## エラー時

`not allow-listed`はパラメーターグループの`azure.extensions`、preloadエラーは`shared_preload_libraries`と再起動を確認します。`ai.search`不在は拡張バージョン・サービス配信状況、モデルの認証・429・タイムアウトはモデル状態・クォータを確認してください。エラーを無視して次の段階へ進まず、設定変更後は失敗したSQL文だけを再実行します。DDL全体を繰り返すと既存オブジェクトと衝突します。
